# CI via GitHub Actions, required status checks on main, no CD yet

No CI existed before this decision — `main` had no branch protection (confirmed via `gh api repos/.../branches/main/protection`, 404) and nothing ran `package.json`'s existing `test`/`typecheck`/`build` scripts automatically. We're adding a GitHub Actions workflow with three parallel jobs (`test`: `vitest run`, `typecheck`: `tsc -b --noEmit`, `build`: `tsc -b && vite build`) on Node 22, triggered on `pull_request` into `main` and on `push` to `main`, with npm dependency caching and a concurrency group that cancels superseded runs. All three jobs become required status checks on `main`, so a PR can't merge until they're green — the `pull_request` trigger is what actually gates the merge button; the `push` trigger is a secondary net for the rare direct push that bypasses a PR (admin override, or protection misconfigured). No required PR review, since Phil is the sole committer.

Deliberately excluded: a lint job — no ESLint config exists yet, and adding one is a separate tooling decision, not a rider on this one. Also excluded: CD — `ROADMAP.md` frames the prototype as "reachable with just a link," which implies hosting eventually, but no deploy target (Pages/Vercel/Netlify) has been chosen, and picking one deserves its own decision.
