# Save/progress as a single JSON blob, keyed by level id

The original's `GameSaveHelper`/`GameProgressSaveManager` used flat, unprefixed `PlayerPrefs` keys (`CurrentLevel` int, `HasSeenHowToPlay` bool) — no nested structure to mirror, so the `localStorage` port had a free choice between flat keys (one `localStorage` key per field, matching the original 1:1) and a single JSON blob. We chose a single blob under `localStorage["rebounder:save"]`: `{ highestUnlockedLevelId: string, hasSeenHowToPlay: boolean }`. One key is simpler to reason about (one read, one write, no partial-write inconsistency between fields) and costs nothing here — the save data is tiny and never needs field-level access outside the save module itself.

Progress is stored by level `id`, not array index or the original's raw `CurrentLevel` int — the curriculum order is regenerated by the scene converter (ADR 0007) and could plausibly be reordered later, and an id survives that where an index wouldn't. If `localStorage` is unavailable (throws, or absent, e.g. private-browsing restrictions in some browsers), the module falls back silently to an in-memory store for the session rather than surfacing an error — progress just doesn't persist across reloads in that case, which is an acceptable degradation for a fully client-side game with no account system. No schema version field: the shape is simple enough that YAGNI applies; add one if the blob's shape ever needs to change under existing save data.

Full design: [issue #33](https://github.com/philjhale/rebounder-ts/issues/33).
