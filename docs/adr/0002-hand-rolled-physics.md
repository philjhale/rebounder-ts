# Hand-roll collision instead of adopting a physics library

Unity's PhysX collision resolution isn't in the source (it's the engine, not code), so this has to be rebuilt regardless of target platform. The collision surface the game actually needs is narrow: constant-speed circles (Balls) against line segments (Lines, Teleporter/ColourChanger triggers) and axis-aligned boxes (Obstacles) — no mass, friction, joints, or stacking. We considered Matter.js / planck.js for broad-phase collision and restitution, but rejected them: that machinery solves problems this game doesn't have, and `Ball.ts` will re-normalize velocity to a constant speed every frame exactly as `Ball.cs` does today, which a general physics engine would fight rather than help with. Paired with this: the game loop runs on `requestAnimationFrame` with variable delta-time (not a fixed-timestep accumulator), mirroring the original's frame-independent speed normalization. Revisit fixed-timestep only if collision tunneling shows up at low frame rates once more levels (denser geometry) are ported.
