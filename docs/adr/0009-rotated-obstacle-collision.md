# Rotated-obstacle collision via a local-space transform wrapper, not a new primitive

ADR 0002 hand-rolled circle-vs-axis-aligned-box collision (`circleVsBox`) because the game's actual collision surface is narrow. The scene converter (ADR 0007) surfaces obstacles with real rotation (28 instances across 8 scenes, `ObstacleData.angle`), which `circleVsBox` can't handle as-is. We considered a general oriented-bounding-box / SAT (separating axis theorem) routine, but rejected it: it's a new collision primitive for a case fully solvable by reusing the existing one. Instead, `angle` is degrees, 0° = unrotated, clockwise-positive — matching `LauncherData.angle`'s existing convention — and collision is a coordinate-transform wrapper: rotate the ball's world position by `-angle` around the obstacle's centre, run the existing unmodified `circleVsBox` in that local space, then rotate the resulting normal by `+angle` back to world space. `reflect()` and its call site in `simulation.ts` need no changes, since the wrapper preserves the existing `Collision` return shape.

The equivalent applies to rendering: the existing tiled-pattern `drawObstacle` is wrapped in a `save`/`translate`/`rotate`/`translate`/`restore` transform rather than rewritten, so the tile grid rotates along with the obstacle. Both wrappers share a single `rotatePoint(point, angleDegrees, origin): Vec2` helper rather than duplicating the trig at each site. Revisit only if a future obstacle shape (non-box) needs collision that this transform trick can't express.

Full design: [issue #36](https://github.com/philjhale/rebounder-ts/issues/36).
